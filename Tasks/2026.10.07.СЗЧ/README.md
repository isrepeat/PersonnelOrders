# Повторение результата СЗЧ за сентябрь 2026

Этот комплект воспроизводит согласованный результат чата: 193 сентябрьских зачисления → 75 совпадений с источниками СЗЧ → 20 людей, фактически прибывших в сентябре. Это снимок данных, а не автоматически обновляемая книга: после изменения исходников запускать скрипт повторно.

## Запуск

В PowerShell из корня репозитория:

```powershell
& './Tasks/2026.10.07.СЗЧ/scripts/run.ps1'
```

По умолчанию `РУХ_last.xlsx` ищется на системном рабочем столе. В текущем окружении это `C:/Users/isrepeat/OneDrive/Рабочий стол/РУХ_last.xlsx`. Можно передать путь и имя результата:

```powershell
& './Tasks/2026.10.07.СЗЧ/scripts/run.ps1' -MovementPath 'C:/Users/isrepeat/OneDrive/Рабочий стол/РУХ_last.xlsx' -Month '2026-09' -OutputPath 'C:/WORK/Windows/Строевые приказы/outputs/szch-20261007/СЗЧ_повтор.xlsx'
```

По умолчанию книга сохраняется в подпапку `Результат`. Если файл занят Excel, скрипт сохраняет новый файл с числовым суффиксом и сообщает его путь. Рядом создаются служебный предпросмотр `.szch-preview.png` и диагностический `.inspect.ndjson`; это не дополнительные результаты для передачи пользователю.

Нужны Node.js, Python с `openpyxl` для чтения и пакет `@oai/artifact-tool` для создания книги. `run.ps1` использует комплект среды Codex из профиля пользователя. В другом окружении агент должен вызвать `load_workspace_dependencies`, указать актуальные пути в `SZCH_PYTHON` и `SZCH_NODE_MODULES` и запустить `build.mjs` найденным Node.js. Не устанавливать зависимости в репозиторий и не заменять создание книги на openpyxl: он используется только для чтения.

После создания `run.ps1` автоматически запускает `verify.py`: проверяются списки, цвета, даты, счётчики, умные таблицы, ширины и отсутствие закрепления. Для отдельной сверки итоговых ФИО, ИПН и дат с согласованным образцом запустить Python среды Codex с аргументами `scripts/verify.py <путь к результату> --reference <путь к образцу>`.

## Какие источники используются

1. `0000. СЗЧ по ухвалі суду 05_10_2026.xlsx`, `Лист1`: ФИО B, ИПН C, данные со строки 2.
2. `00000. СЗЧ_через_БРЕЗ_новий_алгоритм_на 05.10.2026.xlsx`, `Лист1`: ФИО C, ИПН K, данные со строки 2; заголовки партий исключаются.
3. `Поіменний список рапортів СЗЧ (1).xlsm`, `Аркуш1`: ФИО C, ИПН D, данные со строки 3. Статус рапорта не является дополнительным фильтром: требуется само присутствие в списке.
4. `РУХ_last.xlsx`: `Список`, данные со строки 6, ФИО B, ИПН C, `Зарахування` D; `Прибулі`, таблица `ТП`, данные со строки 6, ФИО C, `Прибуття` H, `Вибуття` K, `Додаткова інформація` S.

Другие листы в трёх источниках СЗЧ в согласованный отбор не входят. Текущие числа записей источников: 82 / 432 / 128.

## Правила сверки и даты

ФИО приводится к верхнему регистру; убираются пробелы и пунктуация, `Ґ` заменяется на `Г`, `Ё` на `Е`. Сначала ищется полное нормализованное совпадение. Если его нет, допускается совпадение непустого ИПН. Так подтверждён вариант `БАРАНОВ Дмитрій / Дмитро Миколайович`.

Для остальных сохраняются три ближайших варианта по `difflib.SequenceMatcher` и показатель сходства. Они не включаются автоматически. Совпадающие имя и отчество при другой фамилии недостаточны. Расхождения ИПН при точном полном ФИО отмечаются: у Сухомлина и Фисенко. В исходной сентябрьской выборке пять пустых ИПН; строки сохраняются.

События ТП для человека сопоставляются по нормализованному полному ФИО. Среди прибытия не позже его зачисления берётся последнее; порядок при одинаковой дате уточняется номером исходной строки. Далее скрипт идёт назад по связанной цепочке смены статуса: выбытие предыдущей записи равно прибытию следующей, а предыдущее примечание содержит `Зміна статуса`. Используется дата `Прибуття` этой предыдущей записи. Обычное старое прибытие без такой связи не подменяет последнюю поездку.

«Фактическое прибытие» означает выбранную по этой процедуре дату. В третьем полном списке она может отсутствовать, если событие не найдено. В четвёртом итоговом списке все даты заполнены. Например, Меньков: 10.09.2026; событие 14.09.2026 — продолжение после смены статуса.

Если в новых данных ФИО в ТП отличается или несколько цепочек неоднозначны, проверить кандидатов вручную и явно описать решение; текущий скрипт не делает неподтверждённого неточного объединения событий ТП.

## Вид итоговой книги

Первый лист `Этапы фильтрации`: A:C — все зачисленные, E:G — сверка СЗЧ, I:K — фильтр прибытия, M:O — чистый итог. Первые три блока содержат весь исходный список, выровненный построчно. В E:G розовым отмечены 118 исключённых; в I:K — 173, включая 118 исключённых раньше и ещё 55 на этапе ТП. Третий и четвёртый блоки показывают дату фактического прибытия; первые два — зачисления.

Все четыре блока — умные таблицы Excel с фильтрами, без закрепления. Полные сверка и история находятся на двух дополнительных листах: всего шесть умных таблиц. Фон тёмный, заголовки синие; ширина ФИО 30, ИПН 15, даты 14. ИПН и даты центрированы по высоте и ширине. Розовая подсветка является частью снимка отбора и создаётся заново при запуске.

## Проверка файлов репозитория

Изменять текст только через `apply_patch`. После него отдельной командой разрешено срезать исключительно конечные CR/LF; не удалять пробелы или табуляцию этой командой. Затем проверить последний байт каждого текстового файла из объединения `git diff --name-only` и `git ls-files --others --exclude-standard`: строгие числовые сравнения с 9, 10, 13 и 32. Бинарные книги и картинки в эту текстовую проверку не входят.
