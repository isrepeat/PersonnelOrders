# 01.Food — питание по рапортам

Пользователь создаёт папку `Sources/YYYY.MM.DD` и помещает в неё фотографии. Эта дата определяет дату приказа и папки результатов; сегодняшняя дата, дата получения фото и начало питания для этого не используются. Номер приказа и подписант берутся из единственной строки `tbOrders` в `Tools/Накази.xlsx` на дату имени папки.

- `Sources/YYYY.MM.DD/` — неизменяемые исходники пользователя.
- `Results/YYYY.MM.DD/` — таблица `vN Рапорти_продовольче_сухпрод_YYYY.MM.DD.xlsx` и выписки в `Extracts`.
- `Work/YYYY.MM.DD/` — проверенная расшифровка `reports.json`, описание шаблонов, промежуточные файлы, Word/Excel-рендеры и проверки.

Основные правила оформления и заполнения находятся в `AGENTS.md`. Для сухпайка заполняется только `Сухпрод`; снятие с продовольственного обеспечения без выдачи сухпайка записывается в `Продовольче`. Зачёркнутые лица не включаются. Основания начинаются со строчной буквы, дополнительные сведения и звания из рапортов сохраняются в колонках сверки после основных колонок. `Додаткова інформація` остаётся пустой.

После просмотра всех фотографий создать через apply_patch `Work/<дата папки Sources>/reports.json` по схеме текущего запуска. Тип документа — `dry` или `removal`; указать реальные источники, людей, основание и регистрацию. Скрипты не распознают новые фотографии самостоятельно и не заменяют визуальную сверку.

Основные команды принимают дату явно:

```text
python Tools/process_food_reports.py --date YYYY.MM.DD
node Tools/build_food_reports.mjs --date YYYY.MM.DD --output Tasks/01.Food/Work/YYYY.MM.DD/workbook.xlsx
python Tools/copy_food_reference_format.py <таблица.xlsx> <образец РУХ_last.xlsx>
python Tools/build_food_extracts.py --date YYYY.MM.DD
python Tools/build_food_sections.py --date YYYY.MM.DD
python Tools/verify_food_outputs.py --date YYYY.MM.DD --workbook <таблица.xlsx>
```

Использовать bundled Node/Python, не системные интерпретаторы. Перенос проверенной таблицы из Work в Results выполняется под следующим свободным номером версии; выписки именуются по актуальному шаблону. Перед повторной сборкой существующих выписок сохранить прежние файлы в `Work/<дата>/Versions`. Выпускать документы после просмотра всех страниц Word-рендера и проверки сохранности исходного шаблона. Если штатный DOCX-рендерер недоступен, использовать установленный Word и bundled Poppler.
