# Регулярная обработка рапортов по питанию

- Пользователь вручную создаёт папку `Sources/YYYY.MM.DD` и помещает в неё исходники. Дата запуска, папок `Results` и `Work`, имени таблицы и приказа берётся исключительно из имени этой папки. Не использовать сегодняшнюю дату, дату получения фото, начало питания или дату рапорта для выбора приказа.
- Каждый запуск обрабатывает только исходники выбранной папки. Результат — таблица продовольствия/сухпайка и выписки по соответствующим шаблонам из `Documents/Templates/Extracts [food]`. Даты и номера исходных документов сохранять отдельно от даты приказа.
- Исключения для старого запуска `Sources/2026.10.08`: только пять фотографий WhatsApp, без прежних DOCX и списка КОСЬКА. Эти исключения не распространяются на новые папки. Три фотографии КОРНЕНКА образуют один рапорт на 76 человек.
- Рапорты МОРОЗОВИЧА и МІЗЯКА относятся к шаблону снятия с котла и выдачи сухпайка `[НАШИ]`. Для другого рапорта шаблон определять по содержанию и принадлежности военнослужащих.
- Дату, номер и подписанта приказа сопоставлять по `tbOrders` в `Tools/Накази.xlsx`. Отсутствующие ПІБ, звание, дату приказа или номер входящего документа не придумывать; явно запрашивать необходимые сведения.
- Исходный рапорт выражает запрос, а не подтверждает издание приказа. До подтверждения приказа выписка является проектом.
- По рапортам на сухпай заполнять только `Сухпрод`; не дублировать снятие с котлового в `Продовольче`. Документы о снятии с продовольственного обеспечения без сухпайка вносить в `Продовольче`, заполняя дату и номер приказа в колонках `Виключення` и `Виключення.Наказ`. Зачёркнутых в подписанном документе лиц не включать; фиксировать исключение в рабочих данных. Прекращение сухпайка считать первым днём без сухпайка, используя формулу `=[@Початок]+[@Тривалість]` и calculatedColumnFormula таблицы.
- Таблицы оформлять в тёмной теме; фон пустой области листа тоже тёмный. Не закреплять строки и столбцы.
- Не добавлять в документы «Не отрывать от следующего» (keepNext), запреты разрыва абзацев или принудительные разрывы страниц ради компоновки; расположение пользователь корректирует самостоятельно. Сохранять параметры исходного шаблона.
- Во всех документах, генерируемых из шаблонов, явно устанавливать украинский язык проверки орфографии и грамматики (`uk-UA`) для всего текста, включая заголовки, списки, основания, таблицы и колонтитулы. Проверку не отключать: не применять noProof или «Не проверять правописание и грамматику», не отключать проверку в настройках документа. Язык не оставлять на автоматическое определение; перед выдачей проверять, что у сгенерированного текста задан uk-UA.
- Общий документ разделов питания именовать `Template_<месяц>_<номер приказа>.docx`, например `Template_10_293.docx`; это правило заменяет прежнее имя `Продовольче_...`. Перед заменой уже существующего файла сохранять его копию в Work/Versions.
- Зачисление на продовольственное обеспечение без сухпайка вносить в «Продовольче» с датой и номером приказа в «Зарахування»/«Зарахування.Наказ»; поля снятия оставлять пустыми. Если один рапорт содержит снятие и зачисление, создавать отдельную выписку для каждой операции. Для внешних военнослужащих зачисление оформлять по шаблону «зачислить на продовольствие [ЧУЖИЕ]», в {EnrollmentDate} подставлять только дату словами.
- Форматы ячеек и ширины основных колонок B:J переносить непосредственно из таблицы листа Сухпрод в РУХ_last.xlsx. Дополнительные колонки помещать после J. Розовый фон повторов сохранять через conditionalFormatting duplicateValues. Для результатов сверки разрешены сигнальные цвета ПІБ: оранжевый #F4B183 — ПІБ рапорта заменено значением ШПО; голубой #BDD7EE — найден иной вариант ПІБ в истории; жёлтый #FFF2CC — недостаточные данные/предупреждение; красный #F4CCCC — противоречие нового указания истории. Красный имеет приоритет, затем оранжевый, голубой и жёлтый; остальные причины всегда перечислять в замечаниях. Эти сигнальные цвета имеют приоритет над розовым выделением повторов.
- После переноса форматов явно сохранять тёмную чёрную шапку и полосатые строки #262626/#383838 с белым текстом: исходные стили РУХ в тёмном режиме Excel могут не содержать явной заливки. Установа оранжевая, прекращение голубое. Не превращать таблицу в белую.
- В выписках дату приказа брать из имени папки `Sources/YYYY.MM.DD`, номер и подписанта — из единственной строки `tbOrders` этой даты в `Tools/Накази.xlsx`. При отсутствии или неоднозначности строки не подставлять соседний приказ. Период писать словами: «з 12 по 14 жовтня 2026 року:»; на стыке месяцев «з 29 вересня по 01 жовтня 2026 року:». В {RemovalDate} подставлять только дату словами, например «12 жовтня 2026 року», без «сніданку» и других уточнений; предлог «з» сохраняется из шаблона. Основание по умолчанию начинается с «рапорт», включая документы внешних частей: «рапорт командира військової частини ...»; «лист» использовать только по прямому указанию пользователя. Реальные реквизиты документа сохранять. Инициалы сверять по полному ПІБ автора в ШПО; для внешнего автора использовать доступные данные документа, не выдумывать отчество. Строку о поновлении на котловое в выписку сухпайка не добавлять.
- Версионность применять только к таблице рапортов: `v<Version> Рапорти_продовольче_сухпрод_<дата>.xlsx`. Сохранять предыдущие версии, новую создавать со следующим свободным номером. Выписки не переименовывать по этому правилу.
- Додаткова інформація оставлять пустой. Підстава в ячейках по умолчанию начинается с маленькой буквы: «рапорт ...»; «лист ...» использовать только по прямому указанию пользователя. Подтверждённые номера старого запуска от 08.10.2026: КОРНЕНКО 1656/26791-в, МОРОЗОВИЧ 1656/26786-в, МІЗЯК 1656/26790-в; не переносить их в новые документы.
- Колонку Наказ заполнять числовым номером из tbOrders по дате папки Sources; не оставлять пустой, если номер есть в справочнике. Для `Sources/2026.10.08` — №291, для `Sources/2026.10.09` — №292; подписанта каждый раз читать из справочника.
- Между фамилией автора рапорта и инициалами использовать неразрывной пробел U+00A0 в выписках и в основании таблицы.
- Если полного ПІБ автора нет в ШПО, не сокращать известное имя до инициалов: использовать «Имя ФАМИЛИЯ» в грамматическом падеже основания, например «рапорт майора Юрія КОРНЕНКА».
- Имя файла выписки получать из имени выбранного актуального шаблона заменой плейсхолдеров, включая `{Raporter}`. Raporter — фамилия автора в именительном падеже прописными буквами. Использовать шаблоны «сухпай [НАШИ]», «сухпай [ЧУЖИЕ]» или «снять с продовольствия [ЧУЖИЕ]» по содержанию документа; не подменять их старыми именами.
- В Raport и в основании таблицы указывать должность автора из подписанного рапорта в родительном падеже перед званием и именем: «рапорт командира ... капітана ...». Не заменять её кодом посады из ШПО.
- В шаблоне «снять с продовольствия [ЧУЖИЕ]» плейсхолдер `{FoodCard}` заполнять только по содержанию исходного рапорта: если явно просят выдать продовольственный аттестат, заменить его точным текстом «Видати продовольчий атестат.», сохранив оформление абзаца. Если такого запроса нет, удалить весь абзац с `{FoodCard}`, а не оставлять пустую строку. Не выводить необходимость аттестата только из факта снятия с питания или убытия в отпуск. При переносе в общий документ разделов сохранять эту строку, если она присутствует в выписке. Удаление необязательного абзаца FoodCard — разрешённое исключение из правила сохранения абзацев шаблона.
- Для наших рапортов не включать «військової частини А7383» в Raport и основание таблицы. Для чужих сохранять принадлежность к части.
- В списках военнослужащих выписок звание и полный ПІБ писать в украинском знахідному відмінку (кого?): «солдата ШАРКА Євгенія Івановича». Проверять морфологию каждой части ПІБ: мужские фамилии на -ко/-енко — УСТИМЕНКА, БОНДАРЕНКА; фамилии на -а/-я — ЧМАЛУ, ДЗЬОБУ; имя Микола — Миколу. Не приписывать окончание к неизменённой фамилии. Формы основания («рапорт командира ...», КОСЬКА, КУЛЬБІДИ) остаются в родительном падеже. В таблице ПІБ остаётся в именительном падеже.
- При заполнении DOCX заменять только текст плейсхолдеров, включая разбитые между фрагментами: сохранять pPr, rPr, шрифты, отступы, интервалы, табуляцию, пустые абзацы и оформление подписей исходного шаблона. Не уменьшать шрифт и не удалять абзацы ради сокращения числа страниц. Список наследует оформление абзаца периода шаблона; перед основанием добавлять пустой абзац того же шаблона. Последний пункт списка заканчивать точкой, остальные — точкой с запятой; основание заканчивается «).», как в шаблоне.
- Числа и даты хранить типизированными, ІПН — текстом. Не сопоставлять человека только по фамилии. Сохранять основание и ссылку на конкретный исходный файл.
- Готовые результаты хранить только в `Results/<дата папки Sources>`, выписки — в подпапке `Extracts`. Вспомогательные материалы сохранять только в `Work/<та же дата>`. Скрипты запуска должны принимать дату явно и не содержать дату запуска или реквизиты отдельных рапортов как значения по умолчанию.
- При наличии общего шаблона `Template_{mm}_{OrderNumber}.docx` создавать документ разделов питания: переносить заголовок раздела, период/дату, список и основание из выписок в плейсхолдер операции и принадлежности (`EnrollToFoodSupport`, `RemoveFromFoodSupport`, `GiveDryFood`; `_Ours` для А7383, `_Others` для внешних частей). Общую шапку выписки, герб и подписи не переносить. Одинаковые заголовки внутри категории объединять: один заголовок с NN, далее отдельные блоки частей со своими датами, списками и основаниями. Разные заголовки не объединять. Пустые категории очищать вместе с NN. Результат именовать `Template_<месяц>_<номер приказа>.docx`, перед заменой сохранять предыдущий файл в Work/Versions. Не добавлять keepNext или управлять разрывами страниц.
- В создаваемых документах и текстах оснований использовать только прямые двойные кавычки U+0022 (`"`), не «ёлочки» и не типографские двойные кавычки.
- При каждом формировании таблицы обязательно проверять историю на листах Продовольче и Сухпрод актуального настольного РУХ_last.xlsx. Оригинал не изменять. Для воспроизводимого запуска сохранять неизменяемый снимок в Work/<дата> под новым именем, путь указывать в history_snapshot рабочих данных. Если файл заблокирован, использовать доступный открытый экземпляр Excel для SaveCopyAs либо запросить освобождение файла; не подменять актуальную историю старым образцом оформления. В проверке фиксировать путь и SHA-256 снимка.
- Проверять отсутствие открытого зачисления при снятии, повторное зачисление в открытый период, зачисление/снятие во время действующего сухпайка, пересечение сухпайков, несоответствие периода сухпайка явно известным периодам питания, противоречивые указания текущего пакета. Интервалы трактовать как [начало, прекращение): периоды 24–26 и 27–29 не пересекаются. Отдельно отмечать ошибочные даты и пересечения, уже существующие в истории. Отсутствие записей само по себе не доказывает отсутствие обеспечения; для А7383 отсутствие базового зачисления не превращать в доказанный конфликт без иных событий.
- По А7383 сверять полный ПІБ с актуальным ШПО. Если точного совпадения нет, искать наиболее близких кандидатов по нескольким частям ПІБ. Однозначный существенно более близкий вариант допускается использовать с оранжевой отметкой, исходным ПІБ, причиной и указанием автоматического сопоставления; неоднозначные варианты не заменять молча, выводить кандидатами. Подтверждённые пользователем соответствия сохранять явно в рабочих данных. ІПН использовать как идентификатор при его наличии; не объединять людей только по фамилии.
- Исторические варианты ПІБ искать на обоих листах даже при наличии точных записей в другие даты. Учитывать проверенные исходные варианты и формы склонения; близкие неподтверждённые варианты обозначать кандидатами, не выдавать за доказанную личность. Не исправлять сам РУХ в рамках обработки рапортов. Указывать лист, строку, даты и характер расхождения. Проверять также предыдущие обработанные рапорты из Sources/Work, отличая запрос рапорта от подтверждённого внесения в РУХ и не считая один источник дважды.
- Последняя колонка каждого листа результата — Зауваження. В ней описывать все замены ПІБ, исторические варианты, предупреждения и противоречия, включая исходные значения и ссылки на строки РУХ. Колонку Додаткова інформація по-прежнему оставлять пустой. Противоречивое указание не удалять из результата и не исправлять даты по догадке: сохранить запрос и явно выделить его для проверки пользователем.
