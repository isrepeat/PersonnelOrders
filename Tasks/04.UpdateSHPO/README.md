# Регулярное обновление ШПО

Обновлять настольную книгу `ШПО_new.xlsx` по указанной пользователем версии «Додатка 2», пополняя `ПІБ.xlsx`, `Посади.xlsm` и справочники в ШПО. Дату запуска брать из выбранного приложения. Если за дату есть несколько редакций, зафиксировать, какая использована.

## Подготовка

1. В `Sources/YYYY.MM.DD` хранить неизменяемые снимки приложения, `ШПО_old.xlsx`, исходного состояния `ШПО_new.xlsx`, `ПІБ.xlsx` и `Посади.xlsm`. При наличии сохранить официальный список соответствий кодов, например «Зміна індексів.xlsx». Перед заменой настольных файлов сохранить резервные копии их актуальных версий.
2. `ШПО_old.xlsx` использовать как базу сравнения штатных изменений. Наличие строк, которые уже перенесли, проверять по актуальным справочникам настольных книг. Саму старую книгу сохранять как исходник. Работать с копиями, промежуточные материалы хранить в `Work/YYYY.MM.DD`.

## Порядок обновления

1. **ОС.** Полностью заменить содержимое листа «ОС» в рабочей копии `ШПО_new.xlsx` листом «Особовий склад» из выбранного приложения. Удалить первые две строки источника, чтобы исходная третья строка стала шапкой в строке 1. Переносить весь лист по данным, включая «ПРИК» и пустые штатные позиции. Сохранить имя «ОС» и проверить совместимость существующих формул, таблиц, имён и ссылок. При необходимости заменять содержимое существующего листа с восстановлением диапазонов, чтобы удаление объекта листа не создало `#REF!`. Остальные листы ШПО сохранять.
2. **Люди и АЛФ.** Для пополнения брать основные поля ПІБ, ІПН и пола из приложения, исключая строки с кодом «ПРИК» в поле «Код». Сверять отдельно с «ОС» в `ПІБ.xlsx` и с «АЛФ» в ШПО по ІПН как тексту, сохраняя начальные нули. Одинаковый ІПН с одинаковым ПІБ переносить один раз, повтор фиксировать. Пустой или нечисловой ІПН, разные ПІБ при одном ІПН и одинаковые ПІБ с разными ІПН фиксировать отдельно для проверки; совпадения по имени сами по себе не основание для объединения.
3. **Склонение ПІБ.** Добавить отсутствующих людей в конец `ПІБ.xlsx`, заполнить исходные поля, протянуть формулы итоговых и вспомогательных колонок из исправной строки и пересчитать с листом «Винятки». Проверить пол, родительный, дательный, винительный и формы с инициалами. В «АЛФ» добавлять готовые значения в порядке её заголовков, в том числе для тех, кто уже есть в `ПІБ.xlsx`, но отсутствует в «АЛФ». Расхождения существующих записей сообщать отдельно.
4. **Должности.** Сравнить коды и полные названия должностей из приложения со старым «ОС» и проверить наличие кодов в обеих актуальных таблицах «Посади». Учитывать штатные позиции независимо от наличия человека. Для прежнего кода с изменённым названием обновить существующую строку в обеих книгах после проверки различий, включая пробелы, дефисы и регистр. Подтверждённые замены индексов, новые должности и предполагаемые соответствия отмечать разными статусами. Похожие названия или подразделения сами по себе не подтверждают замену. Служебные коды A1… не включать в список обычных замен автоматически; при необходимости проверить их отдельно.
5. **Склонение должностей и перенос.** Добавить подтверждённые новые коды, включая новые коды подтверждённых замен, в конец таблицы «Посади» в `Посади.xlsm`. Получить и проверить родительный, винительный и дательный по логике этой книги, затем перенести код, название и готовые формы в конец таблицы «Посади» в `ШПО_new.xlsx`. Для прежних кодов переносить обновлённые формы в существующие строки. Старые коды при замене сохранять для обратной совместимости. Уже готовые формы переносить без повторного запуска VBA. Новые строки выделять одинаково в обеих книгах; принятые цвета — светло-зелёный `#E2F0D9` для новых кодов подтверждённых замен, светло-голубой `#DDEBF7` для новых должностей. Предполагаемую пару можно провести как добавление отдельного кода после подтверждения пользователя, сохранив статус связи со старым кодом.

## Проверка и выпуск

- Перед заменой настольных файлов обязательно выполнить три отдельных сравнения в TableDiff. Сравнить готовые `ШПО_new.xlsx`, `ПІБ.xlsx` и `Посади.xlsm` с исходным снимком каждой той же книги до обновления из `Sources/YYYY.MM.DD`. `ШПО_old.xlsx` остаётся базой сравнения штата.
- По отчётам TableDiff сверить замену «ОС» с приложением, изменения «АЛФ» и «Посади» в ШПО, а также добавленные и исправленные записи в двух настольных справочниках. Проверить, что прочие изменения объясняются согласованным обновлением. Необъяснённые изменения разобрать до выпуска. Сохранить три отчёта в `Work/YYYY.MM.DD` и указать результаты сверки в итогах запуска. Проверка TableDiff дополняет открытие в Excel, проверку формул и сохранности VBA.
- До финальной записи проверить обе пары справочников на дубли ключей, совпадение перенесённых значений и попадание новых строк внутрь таблиц Excel. Проверить, что требуемые коды и ІПН из нового «ОС» находятся в справочниках. Служебные строки и исключённые записи учитывать отдельно. В отчёте перечислить отсутствующие ключи, дубли, конфликты и ошибки формул, которые требуют ручной проверки.
- Открыть готовые копии в Excel, проверить шапку «ОС», количество строк, формулы и ссылки, отсутствие запроса на восстановление. Проверить сохранность таблиц и VBA-проекта `Посади.xlsm`. Только после проверки заменить настольные рабочие файлы. Повторный запуск сверять с текущими справочниками, чтобы уже перенесённые записи не добавлялись повторно.
- В `Results/YYYY.MM.DD` хранить актуальные готовые копии и отчёт. Каждой генерируемой книге добавлять суффикс `_vNNN`. У настольных рабочих книг сохранять привычные имена. В следующей версии таблицы остатка оставлять только ещё не перенесённые строки, предыдущие версии хранить в `Work/YYYY.MM.DD/Versions`. Для новых отчётных таблиц применять оформление и колонку «Додано у версії» по `Tasks/AGENTS.md`; рабочие справочники сохраняют свои схемы.
- В итогах запуска указать дату приложения, число обновлённых и добавленных записей для каждой книги, количество нерешённых случаев и пути к файлам. Числа предыдущих запусков не использовать как контроль для новых данных.
