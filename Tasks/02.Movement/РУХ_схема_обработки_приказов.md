# Схема подготовки таблиц РУХ из строевых приказов в Tasks/02.Movement

Этот файл описывает, как из одного приказа по строевой части подготовить отдельную Excel-книгу с событиями для ручного переноса в `РУХ_last.xlsx`.

Приоритетное правило полноты от 27.10.2026: результат содержит ВСЕ прибытия и выбытия, предусмотренные обрабатываемым приказом, независимо от наличия или закрытия этих событий в РУХ. Пользователь может заранее открыть/закрыть строку и поставить временное, неподтверждённое основание. Поэтому совпадающая дата, номер приказа, заполненное основание или закрытый статус в РУХ не являются причиной исключить событие из результата. Основания и даты результата брать из текущего приказа. РУХ использовать для поиска связанной строки, прежнего типа события и выявления конкретных расхождений; не фильтровать по признаку «уже внесено». Все прежние указания пропускать уже внесённые возвращения и закрытия этим правилом отменены. Один и тот же исходный пункт не дублировать внутри результата из-за повторного распознавания; связанные переходы отражать отдельными необходимыми операциями.

Обязательное уточнение: если человек отсутствует в ШПО, самостоятельно восстановить полное украинское ПІБ в именительном падеже из склонённой формы исходника для всех журналов. Не оставлять винительный или родительный падеж в ПІБ; исходный Текст наказу сохранять дословно. Не сопоставлять разных людей только по фамилии; конкретную неустранимую неоднозначность отражать в Проблеми. На Список обязательны колонки Дія, ПІБ, ІПН, УІД, Зарахування, Виключення, Текст наказу; УІД пустая, ширина 5.

Последнее уточнение имеет приоритет над прежними правилами оформления: первая колонка Дія обязательна на всех шести журналах событий. Пустые колонки автоматически не сжимать. Только УІД и За межі имеют ширину 5; даты и ІПН — 12, значения без переноса; Додаткова інформація — 24, ІН — 20, Текст наказу — 120. Заголовки остаются с переносом для читаемости. Кофейный фон всего листа, центрирование и масштаб 80% сохраняются.

Актуальное уточнение оформления 25.10.2026: использовать кофейную палитру сборщика с фоном всего листа, включая свободные ячейки; центрирование и масштаб 80%. Выходные колонки строго соответствуют текущим массивам сборщика и `review_supplementary.mjs`: Список — только ПІБ, ІПН, Зарахування, Виключення, Текст наказу; на Відсутні, Прибули и ТВО нет Дія; на Відсутні есть Додаткова інформація. Названия продовольственных дат движения — Вибуття.ПЗ и Прибуття.ПЗ. УІД и За межі всегда шириной 5, Текст наказу всегда 120, прочие полностью пустые колонки — 3. Действия сохраняются во входных проверенных данных для логики обработки. Это уточнение заменяет прежние требования к перечисленным колонкам и цветам.

Обрабатывать только тот приказ, который назвал пользователь. Не обрабатывать диапазон приказов и не добавлять историю предыдущих дней без отдельного запроса.

Скрипты РУХ находятся в `Tasks/02.Movement/Tools`, схема — в `Tasks/02.Movement/РУХ_схема_обработки_приказов.md`. Общие справочники `ШПО.xlsx` и `Накази.xlsx` находятся в корневом `Tools`. Исходные приказы хранятся в `Documents/Orders/А7383/2026`, Word-шаблоны — в `Documents/Templates`, медицинские документы — в `Documents/PersonnelMedicalReports/2026`, изображения по питанию — в `Documents/Images/Food`. В Git отслеживаются скрипты, правила, схема, `Tools/Накази.xlsx` и файлы `.gitkeep`. Остальные `.docx`, `.xlsx`, `.xlsm` и `.zip` игнорируются.

Перед ручным извлечением обязательно запускать универсальный скрипт `Tasks/02.Movement/Tools/extract_order.py`. Он принимает путь к `.docx`, определяет номер и дату приказа, сверяет ПІБ и звания с `Tools/ШПО.xlsx` и создаёт черновой файл `events_<номер>.csv` с найденными кандидатами событий.

Пример запуска из рабочей папки:


Результат скрипта — первичная выборка, а не окончательное решение. Перед созданием Excel обязательно просмотреть исходные пункты приказа, добавить пропущенные нестандартные события, убрать ложные кандидаты и проверить даты, основания, сопроводительные документы и закрытия ТП.

Актуальные ширины: ПІБ ориентировочно 20, заполненные даты и приказы 9.25; все полностью пустые колонки — 3. На Прибули после ПІБ сохранять ІН, УІД, Посада, Звідки. Основные поля подбирать по ширине экрана при 80%, как описано в разделе оформления; старые фиксированные 3.5 для идентификаторов отменены.

При сборке результатов использовать `Tools/build_review_workbook.mjs` и модуль `Tools/review_supplementary.mjs`. УІД результата оставлять пустой. Заполненная Текст наказу — 120, последней справа; лист Проблеми содержит свои тематические колонки. Масштаб всех листов — 80%, сохраняется `Tools/set_workbook_zoom.py`.

Сохранять результат в `Tasks/02.Movement/Results/YYYY.MM.DD/`, где дата соответствует обрабатываемому приказу. Скрипты запуска, промежуточные материалы и превью хранить в `Tasks/02.Movement/Work/YYYY.MM.DD/`, снимки исходных материалов — в `Tasks/02.Movement/Sources/YYYY.MM.DD/`. Инструменты РУХ находятся в `Tasks/02.Movement/Tools`; общие справочники остаются в корневом `Tools`.

Шаблон имени:

Пример: `РУХ_279_v9.xlsx`.

Перед созданием проверить файлы `РУХ_<OrderNumber>_v*.xlsx` в папке результатов запуска и в `Work/YYYY.MM.DD/Versions`. Новая версия получает следующий свободный номер. Старые версии не удалять и не перезаписывать; при замене актуального результата перенести предыдущую версию в `Work/YYYY.MM.DD/Versions`.

## Сопоставление ПІБ и звания с ШПО

1. Если в пункте приказа указан ИПН, найти запись в `ШПО.xlsx`.
2. Для ПІБ использовать именительный падеж из справочника:
   - лист `АЛФ`;
   - ИПН — первый столбец;
   - ПІБ в именительном падеже — второй столбец.
3. Для звания использовать фактическое звание в именительном падеже с листа `ОС`:
   - ИПН — столбец `ІПН`;
   - звание — столбец `Військове звання фактично`.
4. Если ИПН отсутствует или его нет в ШПО, привести ПІБ и звание к именительному падежу вручную. Не оставлять формы из текста приказа: `КОВАЛЯ Василя Юрійовича` нужно записывать как `КОВАЛЬ Василь Юрійович`.
5. Не подменять человека совпадением только по фамилии.

## Какие события извлекать

Для журналов движения нужны события, влияющие на количество людей на продовольственном или котловом обеспечении. Все упоминания ТВО дополнительно учитывать в отдельном журнале, даже если физического движения нет. Прочие назначения на должности, изменения званий, премии, оклады и итоговый котловой список не превращать в события движения; подозрительные даты кадровых пунктов проверять для листа Проблеми.

### Лист `Прибули`

#### Смена статуса уже временно прибывшего

Перед новым прибытием в ТП или прибытием в служебную командировку проверить в текущей РУХ прежнее незакрытое событие этого человека. Сопоставлять по достоверному идентификатору, а при его отсутствии — по однозначному полному ПІБ, не по одной фамилии. Если новый пункт меняет статус уже временно прибывшего на командировку, оформить переход двумя связанными операциями на `Прибули`: закрыть прежнее ТП датой начала нового статуса и открыть новую строку командировки этой датой. Это смена статуса, а не второе одновременное открытое пребывание.

В закрываемой прежней строке заполнить поля выбытия номером, датой и основанием текущего приказа; прежние поля прибытия и прежнюю часть не заменять. В новой строке заполнить поля прибытия и часть из нового пункта приказа. Продовольственные даты определять отдельно по явным указаниям и общему правилу; смена статуса сама по себе не означает физического выбытия из части или повторного зачисления на питание. Уже внесённое закрытие не дублировать.

В `Додаткова інформація` закрываемого ТП дописать точную фразу: `Зміна статуса з тимчасово прибулого на відрядження.` Существующие сведения сохранить, фразу повторно не добавлять. В отдельной книге результата предусмотреть эту колонку на `Прибули` перед последней `Текст наказу`, если формируется такая операция; одного примечания на `Проблеми` вместо связанной закрывающей строки недостаточно. В `Дія` явно обозначить смену статуса на обеих связанных строках.

Пример пользователя: ТЕГЛІВЕЦЬ Юрій Володимирович, приказ №300: прежнее ТП из А7019 закрывается, новое прибытие в командировку из А4594 открывается 17.10.2026. Различие частей не является основанием оставить обе строки открытыми или ограничиться предупреждением о возможном дубле. Не применять переход автоматически к любому совпадению: новый статус должен подтверждаться текущим пунктом приказа.

Добавлять события:

- зачисление в тимчасово прибулий особовий склад;
- фактическое прибытие временного состава. Отдельные операции только «зарахувати на продовольче забезпечення» для внешних подразделений относить к Продовольче, не к Прибули.

Не записывать сюда военнослужащего, которого ранее временно приняли, а затем в этом же или следующем приказе зачислили до списків особового складу. Это событие относится к листу `Список`.

Лист ведётся как журнал движения временно прибывших: в одной строке фиксируются как прибытие, так и последующее выбытие этого человека. Не создавать отдельную упрощённую таблицу событий. Первая колонка всегда `Дія`, последняя — `Текст наказу`.

Использовать строго такой порядок колонок:

1. `Дія`
2. `Звання`
3. `ПІБ`
4. `Посада`
5. `Звідки`
6. `Прибуття.Наказ`
7. `Прибуття.Продовольче`
8. `Прибуття`
9. `Прибуття.Термін`
10. `Вибуття.План`
11. `Вибуття`
12. `Вибуття.Продовольче`
13. `Вибуття.Наказ`
14. `Прибуття.Підстава`
15. `Супровідний документ`
16. `Вибуття.Підстава`
17. `Текст наказу`

При событии прибытия заполнять поля `Прибуття.*` и `Прибуття.Підстава`, а поля выбытия оставлять пустыми. При событии выбытия уже имеющегося временно прибывшего заполнять поля `Вибуття.*` и `Вибуття.Підстава`; строку сопоставлять по ИПН, если он известен, иначе по ПІБ. Поле `Вибуття.План` заполнять только когда в приказе прямо указан плановый срок или дата выбытия. `Супровідний документ` используется для номеров отпускных билетов и удостоверений о командировке по общему правилу ниже.

Если в пункте о зачислении в списки есть формулировка наподобие `зарахованого до списків тимчасово прибулого особового складу військової частини А7383`, обязательно добавить на лист `Прибули` отдельную закрывающую строку. В ней заполнить `Вибуття` датой зачисления в списки, `Вибуття.Продовольче` рассчитанной продовольственной датой, `Вибуття.Наказ` номером текущего приказа и `Вибуття.Підстава` основанием этого пункта. Поля `Прибуття.*` в такой строке не заполнять.

### Лист `Список`

Добавлять события:

- «зарахувати до списків особового складу» и «на всі види забезпечення»;
- «виключити зі списків особового складу»;
- смерть, увольнение, перевод в другую часть и другие формулировки, прямо исключающие человека из списков или всех видов обеспечения.

Лист также формировать как журнал событий для ручного переноса в целевую таблицу, а не как упрощённый перечень людей. Первая колонка всегда `Дія`, последняя — `Текст наказу`. Для каждого человека фиксировать либо зачисление, либо исключение, не заполняя несоответствующие событию поля.

Использовать строго такой порядок колонок:

1. `Дія`
2. `Звання`
3. `ПІБ`
4. `ІПН`
5. `Зарахування`
6. `Виключення`
7. `В строю`
8. `На продовольчому`
9. `Зараховано на продовольче`
10. `Виключено з продовольчого`
11. `Підстава`
12. `Супровідний документ`
13. `Текст наказу`

Для зачисления в `Зарахування` записывать дату зачисления, а для исключения — дату в `Виключення`. Если текст пункта прямо предписывает поставить или снять с продовольственного обеспечения, проставлять соответствующую дату в `Зараховано на продовольче` или `Виключено з продовольчого` по общему правилу расчёта продовольственной даты. Признаки `В строю` и `На продовольчому` заполнять только когда приказ прямо устанавливает соответствующий статус. В `Підстава` переносить текст после двоеточия из абзаца `Підстава:` до точки, исключая данные отпускного билета или удостоверения о командировке; их номер переносить в `Супровідний документ`. В `Текст наказу` всегда оставлять полный исходный пункт для сверки.

### Лист `Відсутні`

Добавлять события выбытия:

- командировка;
- лечение, госпитализация, отпуск для лечения;
- ежегодный отпуск и отпуск по семейным обстоятельствам;
- СЗЧ, неприбытие из отпуска или лечения;
- безвестное отсутствие и смерть;
- снятие с продовольственного обеспечения;
- выбытие к новому месту службы, если человек остаётся в данных на листе отсутствующих до окончательного удаления из списка.

Добавлять события прибытия, закрывающие отсутствие:

- возвращение из лечебного учреждения;
- возвращение из ежегодного отпуска, семейного отпуска или отпуска для лечения;
- возвращение из командировки;
- возвращение из СЗЧ;
- восстановление на всех видах обеспечения.

## Исключение из списков и закрытие отсутствий

Исключение на листе `Список` не заменяет закрытие открытого события на листе `Відсутні`. Перед обработкой исключения сопоставить человека по ІПН с целевой книгой РУХ и проверить его последнее незакрытое отсутствие. Если книга недоступна или статус неоднозначен, явно отметить необходимость проверки в `Проблеми`; не считать человека находящимся в строю по умолчанию и не придумывать прежнее отсутствие.

Обозначения: `E` — дата исключения из списков, прямо указанная в приказе; `R` — фактическая дата возвращения в другую часть; `S` — дата смерти. Дата приказа, дата исключения, дата закрытия отсутствия и дата продовольствия могут различаться. Ниже приведены специальные правила, имеющие приоритет над обычным заполнением событий.

### 1. Человек находился в строю

Создать событие исключения на листе `Список`: `Виключення = E`. Отдельное закрывающее событие на листе `Відсутні` не требуется, если открытого отсутствия нет. Продовольственную дату брать из приказа, а при отсутствии явной даты — по общему правилу.

### 2. Человек находился в командировке

Создать исключение на листе `Список` с `Виключення = E` и закрывающее событие на листе `Відсутні` с `Прибуття = E + 1 день`. В `Прибуття.Наказ` записать номер текущего приказа, в `Прибуття.Підстава` — относящийся к исключению текст `Підстава:`. Это учётное закрытие командировки, а не утверждение о физическом возвращении человека в часть. Прежние поля выбытия не заменять данными текущего приказа. Продовольственную дату заполнять отдельно по явному указанию приказа либо общему правилу; закрытие само по себе не означает повторное зачисление на питание.

### 3. СЗЧ и возвращение в другую часть

Если пункт содержит возвращение после СЗЧ в другую часть и последующее исключение, сформировать три связанные строки:

- `Список`: исключение с `Виключення = E`.
- `Відсутні`: закрытие прежнего СЗЧ с `Прибуття = R`, номером текущего приказа и основанием в полях прибытия.
- `Відсутні`: новое событие `Повернення до іншої частини`, открытое датой `R` и закрытое датой `E + 1 день`.

В новой строке заполнить `Вибуття = R`, `Вибуття.Наказ` и `Прибуття.Наказ` номером текущего приказа, `Прибуття = E + 1 день`. Для такого учётного перехода `Вибуття.Продовольче` и `Прибуття.Продовольче` новой строки, а также `Прибуття.Продовольче` закрытия СЗЧ равны `E + 1 день`, если приказ прямо не устанавливает другое. В обе колонки основания новой строки перенести соответствующий текст `Підстава:`. В `Куди` сохранить часть фактического возвращения после СЗЧ; дальнейшее назначение и обе части остаются в полном `Текст наказу`.

Пример: ОНОПРІЄНКО Владислав Олександрович, ІПН `3091915199`, приказ №282. Фраза «26 серпня 2026 року повернувся до військової частини А7224» задаёт `R = 26.08.2026`; «з 29 вересня 2026 року виключений зі списків» задаёт `E = 29.09.2026`.

| Строка | Дата открытия / исключения | Прибуття | Прибуття.Продовольче |
| --- | --- | --- | --- |
| `Список`: исключение | `Виключення = 29.09.2026` | — | — |
| `Відсутні`: закрытие СЗЧ | прежнее выбытие не менять | 26.08.2026 | 30.09.2026 |
| `Відсутні`: `Повернення до іншої частини` | `Вибуття = 26.08.2026` | 30.09.2026 | 30.09.2026 |

Для новой строки `Вибуття.Продовольче = 30.09.2026`, оба номера приказа — `282`, часть назначения — `А7224`. Явная историческая дата снятия с питания `14.09.2025` остаётся в `Список.Виключено з продовольчого` и не заменяется датой закрытия отсутствия.

### СЗЧ, возвращение в другую часть и новая командировка без исключения

Если один пункт предписывает возвращение после СЗЧ и направление в новую командировку, выделить две операции: закрытие прежнего СЗЧ и открытие командировки. Дату возвращения `R` брать из фразы `... з [дата] повернувся до військової частини ...`, дату командировки `D` — из `Направити у відрядження ... з [дата]`. Не подменять `R` датой `D` или датой приказа.

- Всегда создать закрытие СЗЧ: `Подія = Самовільне залишення частини`, `Прибуття = R`; прежние поля выбытия не заполнять заново.
- Если `R < D`, дополнительно создать промежуточное `Повернення до іншої частини`: `Вибуття = R`, `Прибуття = D`, `Куди` — часть фактического возвращения. Это не исключение из списка; дату закрытия здесь не увеличивать на день.
- Затем открыть `Відрядження`: `Вибуття = D`, `Куди` — часть новой командировки. В целевой книге вместе с прежним СЗЧ получается три события. В выгрузке три связанные строки располагать подряд: закрытие СЗЧ, промежуточное возвращение, новая командировка.
- Если `R = D`, промежуточную строку не создавать: закрыть СЗЧ датой `R` и открыть командировку датой `D`. Если `R > D`, отметить противоречие для проверки, не создавать отрицательный интервал.
- Номера текущего приказа и очищенное основание переносить в соответствующие поля каждой операции. `Супровідний документ` о новой командировке указывать в строке командировки, не переносить его в закрытие СЗЧ или промежуточное возвращение. Полный исходный пункт сохранять последней колонкой во всех связанных строках.
- При `Поновити ... окрім продовольчого` все продовольственные поля этих операций оставлять пустыми. Иначе определять их отдельно по явным указаниям и общему правилу, не копировать безусловно дату командировки в дату питания закрытия СЗЧ.
- Пример №284, ЧАУСОВ: СЗЧ закрыть `29.09.2026`; `Повернення до іншої частини` в `А7018` открыть `29.09.2026`, закрыть `01.10.2026`; командировку в `А0501` открыть `01.10.2026`. Документ `2026/284/13` относится к новой командировке. Исключение из списка не создавать.

Этот переход автоматически выделяет `return_before_departure` в `Tasks/02.Movement/Tools/extract_order.py`. Не добавлять те же закрытия повторно при ручной сверке.

### 4. Смерть во время незакрытого отсутствия

Правило применяется к `Безвісти зниклий` и любому другому открытому отсутствию, если приказ сообщает о смерти человека вне части. Если короткий пункт только сообщает дату смерти и не устанавливает дату исключения из списков, временно учитывать `Список.Виключення = S` и закрыть прежнее отсутствие на листе `Відсутні` с `Прибуття = S + 1 день`. Это учётная заглушка, показывающая отсутствие человека в части, а не дата официального исключения: оно может быть оформлено спустя недели или годы.

Если приказ явно устанавливает дату исключения из списков, она имеет приоритет над датой смерти и временной заглушкой: `Список.Виключення = E`, закрытие отсутствия `Прибуття = E + 1 день`. При последующем официальном исключении заменить прежнюю заглушку и дату закрытия соответствующего отсутствия, не создавая второе событие смерти или повторное исключение. Пример: МИКИТЮК Юрій Іванович, приказ №278, пункт 16: смерть `09.01.2024`, официальное исключение `11.09.2026`; правильные даты — `Виключення = 11.09.2026`, `Прибуття = 12.09.2026`. ПРОЙДАК Олексій Олександрович, тот же приказ, пункт 17: смерть `07.09.2026`, официальное исключение `08.09.2026`; правильные даты — `Виключення = 08.09.2026`, `Прибуття = 09.09.2026`.

Заполнить номер текущего приказа и основание в полях прибытия. Не создавать фиктивное физическое возвращение и не подменять исходный тип отсутствия смертью. Продовольственные даты определять отдельно; изменение учётной заглушки само по себе не означает повторного изменения питания. Если дата смерти не установлена и нет явной даты исключения, не вычислять их из даты приказа: отметить случай для проверки.

Пример: ВЕЛИЧЕНКО Володимир Володимирович, ІПН `3535707238`: смерть `12.09.2026`, поэтому `Список.Виключення = 12.09.2026`, закрытие отсутствия `Прибуття = 13.09.2026`. В приведённом примере приказа №270 `Прибуття.Продовольче = 18.09.2026`, а не `13.09.2026`: дату продовольствия определять отдельно. В `Прибуття.Підстава` перенести основание о смерти (свидетельство и рапорт) из приказа, сохранив полный пункт последней колонкой.

Универсальный скрипт `extract_order.py` автоматически добавляет закрытие СЗЧ и составное событие `Повернення до іншої частини`, когда в пункте исключения прямо указаны дата возврата в другую часть и возвращение после СЗЧ. В промежуточном CSV отдельные поля `Вибуття`, `Вибуття.Продовольче`, `Прибуття`, `Прибуття.Продовольче` задают даты составного события; при создании Excel они имеют приоритет над общей `Дата події`. Исходная строка исключения с исторической продовольственной датой сохраняется отдельно. Остальные случаи (командировка, смерть, неоднозначный статус) и сопоставление с целевой книгой по ІПН пока проверяются вручную. Наличие правил в этом документе не означает, что скрипт уже автоматизирует все варианты.

## Связь с пунктами приказа

При каждом новом разделе или подразделе сбрасывать прежний контекст. Действие определять по заголовку текущего подраздела: например, «На лікування» после «У відрядження» означает лечение для всех следующих людей до следующего заголовка. Дату из общего абзаца над перечнем применять ко всем людям этого перечня, если персональный пункт не устанавливает другую дату. Зачисление может быть отдельным абзацем после ПІБ; исключение может быть сформулировано как «виключений зі списків». Явные продовольственные даты из приказа имеют приоритет над расчётным правилом.

Для каждой строки сохранить полный абзац с человеком в колонке `Текст наказу`. Это поле служит только для сверки и располагается последним.

Текст основания брать не из абзаца с человеком, а из ближайшего относящегося к нему абзаца, который начинается с `Підстава:`.

- Удалить из результата слово `Підстава:`.
- Сохранить остальной текст основания без завершающей точки.
- Для выбытия записывать его в `Вибуття.Підстава`.
- Для прибытия записывать его в `Прибуття.Підстава`.
- Если один абзац `Підстава:` относится к перечню людей, использовать его для всех строк этого перечня.

Из текста основания удалить фрагменты с `відпускний квиток` и `посвідчення про відрядження`. Номера документов формата `2026/279/XX` или аналогичного записывать через запятую в `Супровідний документ`.

Для временно прибывших на листе `Прибули` удостоверение о командировке обязательно выносить в отдельную существующую колонку `Супровідний документ`, а не оставлять только в `Прибуття.Підстава`. Сохранять номер и дату в формате `ПВ №614 від 15.09.2026`, в том числе для номеров без косых черт. Если в общем основании перечислены несколько ПВ без явной связи с конкретными людьми, не распределять их по порядку фамилий: в каждой относящейся к группе строке сохранить общий список ПВ, а отсутствие персональной привязки отметить на `Проблеми`. Персональное ПВ указывать только при подтверждённом соответствии. Полный исходный текст приказа сохранять дословно в `Текст наказу`.

### Отдельный лист `ТВО`

Все упоминания ТВО во всём приказе разбирать отдельно от физического движения: допуск, принятие обязанностей, продление, сдача, прекращение, возвращение к собственной должности. Не ограничивать поиск пунктами об отпусках. Само назначение не является событием отсутствия.

На `Відсутні` колонки `ТВО.ПІБ`, `ТВО.ІПН`, `ТВО.Посада` больше не создавать. Для `ТВО` использовать структуру актуального РУХ_last: `Дія`, `Звання`, `ПІБ`, `ІПН`, `УІД`, `Посада.Своя`, `Посада.Заміщує`, `Термін`, `Доступ.Наказ`, `Прийняття.Наказ`, `Прийняття`, `Здавання.План`, `Здавання`, `Здавання.Наказ`, `Прийняття.Підстава`, `Здавання.Підстава`, `Додаткова інформація`; для сверки последним сохранять `Текст наказу`. УІД результата пустая.

ПІБ и собственный код посады замещающего сверять с ШПО по ІПН либо однозначному полному ПІБ. `Посада.Своя` — собственная должность замещающего; `Посада.Заміщує` — должность, обязанности которой он выполняет. Не подменять одну другой и не угадывать код по одному названию. Сохранять принятые замены кодов A1A → РОЗП, A1B → СПИС, A1C → ТП.

Перед открытием и закрытием проверять реальную таблицу ТВО текущей РУХ по человеку и замещаемой должности. Не дублировать уже внесённые операции. Возвращение к своим обязанностям также отражать на ТВО как соответствующее закрытие, если однозначно найден открытый период; это не новое назначение. Допуск и фактическое принятие могут иметь разные даты и номера приказов. Срок 6М, дата плановой сдачи и другие значения не являются универсальными значениями по умолчанию: заполнять только при подтверждении источником и согласованным правилом.

Подробные правила переходов будут уточняться с пользователем на примерах. Пока не установлено однозначное действие, сохранить упоминание отдельной строкой ТВО с описанием требуемой сверки в `Дія`, полным исходным пунктом и подтверждёнными полями; предполагаемые даты открытия/закрытия не заполнять. Конкретное препятствие отразить на `Проблеми`.

### Отдельные листы питания

Операции, меняющие только продовольственный учёт, направлять в `Продовольче`, сухпайки — в `Сухпрод`. Не оставлять такие строки на `Прибули` и не создавать физические даты без указания приказа. Физическое прибытие/выбытие и связанное питание в журналах движения сохранять; не создавать вторую самостоятельную операцию питания из одной и той же записи без основания.

Использовать правила таблиц `Tasks/01.Food/AGENTS.md`, сверки истории `Tools/food_history.py` и структуру актуального РУХ_last. Правила выписок DOCX и выбора приказа по папке рапортов не меняют явно обрабатываемый строевой приказ. Текущие пользовательские требования к центрированию, ширинам и `Проблеми` имеют приоритет над прежними стилями Food.

`Продовольче`: `Звання`, `ПІБ`, `Установа`, `Група`, `Зарахування`, `Зарахування.Наказ`, `Виключення`, `Виключення.Наказ`, `Зарахування.Підстава`, `Виключення.Підстава`, `Додаткова інформація`, `Текст наказу`. В строке зачисления заполнять только поля зачисления, в строке снятия — только поля снятия. Группу не придумывать. `Додаткова інформація` оставлять пустой.

`Сухпрод`: `Звання`, `ПІБ`, `Установа`, `Група`, `Початок`, `Тривалість`, `Припинення`, `Підстава`, `Наказ`, `Додаткова інформація`, `Текст наказу`. Прекращение — первый день без сухпайка, формула таблицы `=[@Початок]+[@Тривалість]`; интервал [начало, прекращение). По сухпайку не дублировать снятие с котла в `Продовольче`. `Додаткова інформація` пустая.

Проверять актуальную историю обоих листов: снятие без открытого периода, повторное зачисление, операции питания во время сухпайка, пересечения сухпайков и противоречия пакета. Отсутствие базового зачисления А7383 само по себе не доказывает нарушение. Сохранять оригинальные даты и подтверждённый ПІБ; спорные варианты и ошибочные интервалы вынести в `Проблеми` с листом, строкой и конкретным расхождением. РУХ_last не менять.

### Связанные действия на разных листах

Если операция по человеку на одном листе требует закрытия или создания связанного события на другом листе, в колонке `Дія` отражать обе операции, разделяя их строкой ` | `. На связанных строках разных листов указывать действия симметрично и в одинаковой последовательности, независимо от текущего листа: сначала основная операция по списку, затем операция по связанному событию.

- Например, на листе `Список` и в строке закрытия СЗЧ на листе `Відсутні`: `Виключити зі списку | Закрити СЗЧ`.
- В отдельной строке нового события на листе `Відсутні`: `Виключити зі списку | Повернення до іншої частини`. Строка закрытия СЗЧ при этом сохраняет свою комбинацию действий; не объединять разные события в одну строку.
- При зачислении человека из временного учёта применять тот же принцип к связанным строкам листов `Список` и `Прибули`: отразить зачисление и закрытие временного учёта в одинаковом порядке.
- Связь устанавливать по ІПН и конкретному пункту приказа, а без ІПН — только при однозначном совпадении человека и события. Само присутствие человека на двух листах не является основанием объединять несвязанные действия.
- Это описание операций для ручного переноса, а не дополнительное событие: не дублировать строки, даты или продовольственные изменения из-за составного значения `Дія`.
- Поле `Подія` остаётся отдельным типом конкретного события без разделителя ` | `: например, `Самовільне залишення частини` либо `Повернення до іншої частини`.

### Посада, Подія, Куди и За межі

Для `Подія = Самовільне залишення частини` поле `Куди` всегда оставлять пустым, в том числе при СЗЧ после прекращения командировки и неприбытии к новому месту службы. Часть, которую человек самовольно оставил или куда не прибыл, сохранять только в полном `Текст наказу` и основании, не в направлении события СЗЧ. Например, у ГЛУЩЕНКА в №301 новая строка СЗЧ не должна содержать А1363 в `Куди`.

- `Посада` — именно код из колонки `Код посади` листа `ОС` в `Tools/ШПО.xlsx`, найденный по ІПН. Коды, начинающиеся с `A1A`, полностью заменять на `РОЗП`, с `A1B` — на `СПИС`, с `A1C` — на `ТП`; суффикс исходного кода не сохранять. Остальные коды оставлять без изменений. Не использовать вместо него название должности, колонку `Код` подразделения или код из другой книги. При отсутствии ІПН допустимо точное, однозначное сопоставление полного ПІБ с ШПО; при отсутствии достоверного соответствия оставить пустым и отметить на `Проблеми`.
- `Подія` — тип отсутствия из перечня ниже. `Дія` остаётся первой колонкой и описывает операцию: например, `Закрити СЗЧ` в `Дія` соответствует `Самовільне залишення частини` в `Подія`; прибытие из больницы соответствует `Стаціонарне лікування`. Для нового события возвращения в другую часть `Подія = Повернення до іншої частини`.
- `Куди` — направление, прямо указанное в персональном пункте приказа или в общем абзаце соответствующей группы. При смене подраздела сбрасывать прежнее направление. Для отпуска переносить населённый пункт, для лечения — учреждение, для командировки — часть или организацию. Для `Повернення до іншої частини` брать часть фактического возвращения после СЗЧ, а не последующее место назначения: в №283 ГРИЦАК — `А7018`, КАНІШЕВСЬКИЙ — `А7017`, не `А4018`. Для закрытия отсутствия не придумывать направление; если приказ его не сообщает, оставлять пустым.
- `За межі` — пока всегда пусто, даже если в перечне типов есть значения `Так`/`Ні`.

Допустимые значения `Подія` (точное написание из целевой книги):

1. `Щорічна відпустка`
2. `Відпочинок за донацію крові`
3. `Відпустка за сімейними обставинами`
4. `Відпустка для лікування`
5. `Відпустка у зв’язку з вагітністю та пологами`
6. `Відпустка по догляду за дитиною`
7. `Відрядження`
8. `Стаціонарне лікування`
9. `Самовільне залишення частини`
10. `Повернення до іншої частини`
11. `Полон`
12. `Безвісти зниклий`
13. `Арешт`
14. `Звільнення від виконання службових обов’язків`
15. `Амбулаторне лікування`
16. `Амбулаторне ВЛК`
17. `ВЛК за межами`

Если действие нельзя надёжно сопоставить с перечнем, не вводить новый произвольный тип: оставить `Подія` пустым и отметить строку для проверки. Добавление этих четырёх колонок относится к листу `Відсутні`; структуру `Список` и `Прибули` не менять автоматически. Новые колонки центрировать горизонтально и вертикально, с переносом текста; `Посада` хранить как текстовый код. `Текст наказу` остаётся последней колонкой.

### Заполнение полей выбытия

Для события выбытия:

- `Вибуття.Наказ` — номер приказа без символа `№`, например `279`;
- `Вибуття` — дата события;
- `Вибуття.Продовольче` — дата продовольственного выбытия;
- `Вибуття.Підстава` — очищенный текст ближайшего абзаца `Підстава:`;
- `Супровідний документ` — номера отпускных билетов и удостоверений о командировке;
- поля прибытия оставлять пустыми.

### Заполнение полей прибытия

Для события прибытия:

- `Прибуття` — дата фактического прибытия;
- `Прибуття.Продовольче` — дата продовольственного прибытия;
- `Прибуття.Наказ` — номер приказа без символа `№`, например `279`;
- `Прибуття.Підстава` — очищенный текст ближайшего абзаца `Підстава:`;
- `Супровідний документ` — номер документа, если он указан в основании;
- поля выбытия оставлять пустыми, кроме составного события `Повернення до іншої частини`, где одна строка содержит открытие и закрытие по специальному правилу выше.

### Правило даты продовольственного обеспечения

Пусть дата приказа — `D`.

- Обычно `Вибуття.Продовольче` и `Прибуття.Продовольче` равны `D + 1 день`.
- Если дата самого события позже `D`, дата продовольствия равна дате события.
- Если событие раньше или в дату приказа, использовать `D + 1 день`, если приказ прямо не устанавливает иную дату продовольственного обеспечения.

Например, для приказа от 26.09.2026 событие 26.09.2026 получает продовольственную дату 27.09.2026, а событие 29.09.2026 — 29.09.2026.

## Оформление Excel

Каждый новый результат содержит листы `Список`, `Відсутні`, `Прибули`, `ТВО`, `Продовольче`, `Сухпрод`, `Проблеми`. Лист `Огляд` больше не создавать. Пустые журналы сохранять с заголовками; не добавлять фиктивных людей или событий.

Все рабочие диапазоны — настоящие Excel-таблицы с фильтрами и сортировкой. Масштаб каждого листа — 80%. Не закреплять строки и столбцы. Тёмная тема, чёрные заголовки с белым текстом, белый текст строк на тёмном фоне, Times New Roman 10 pt, перенос текста.

ВСЕ ячейки ВСЕХ таблиц, включая заголовки, ПІБ, Дія, основания, исходный текст, проблемы и примечания, центрировать горизонтально и вертикально. Исключений с выравниванием слева больше нет.

Ширины подбирать по содержимому конкретного запуска, чтобы основные колонки помещались на экране при 80% по образцу пользователя. ПІБ ориентировочно 20, заполненные даты и приказы 9.25. Любую колонку, пустую во всех строках данных, ужимать до 3, включая УІД, ІН, За межі, незаполненные даты и основания. Не считать заполненный заголовок данными колонки. Не скрывать пустые колонки и не терять порядок полей. Полную `Текст наказу`, если она заполнена, оставлять последней справа шириной 120 для сверки; её ширина не должна мешать размещению основных полей. Высоту строк подбирать по переносу текста, не уменьшать шрифт для вмещения.

### Лист `Проблеми`

Это список конкретных вопросов для проверки, а не сводка количеств или журнал обработки. Колонки: `Тип`, `ПІБ / ідентифікатор`, `Лист / пункт / рядок`, `Проблема`, `Значення в джерелах`, `Що перевірити`.

Включать логически невозможные или противоречивые даты, отрицательные интервалы, перекрывающиеся открытые статусы, несогласованные даты принятия должности и зачисления, конфликты идентификации или кодов ТВО, невозможность однозначного открытия/закрытия и расхождения оснований. Например: приказ 18.10.2026, принятие должности 18.09.2026 — показать обе даты и пункт, предложить сверку месяца; не исправлять дату по догадке. Ретроспективная дата сама по себе не ошибка: отделять подтверждённый исторический факт от подозрительной даты.

Не включать обычные сообщения «уже закрыто», «повтор не создан», «исходная книга не изменена», количества строк и описания успешно обработанных операций. Эти сведения хранить в Work и README. Отсутствие в ШПО заносить только если оно оставляет конкретную неоднозначность или незаполненное необходимое поле. Если проблем нет, таблица остаётся без записей.

### Данные сборщика

Новый JSON содержит `records` (физическое движение и операции списка), `tvo` (проверенные строки по всем упоминаниям ТВО), `foodSupport`, `dryRations`, `problems`; дополнительные строки можно передавать в records с явным Лист. Для приказа без движения явно передавать `orderNumber` и `orderDate` (дд.мм.гггг). Строки дополнительных журналов — объекты с указанными выше именами колонок.

Старые notes не переносить целиком в Проблеми: вручную выделить реальные расхождения, остальные записи оставить в Work. Старые food с текстовыми массивами и ТВО.ПІБ/ІПН/Посада требуют подготовки новых объектов; сборщик останавливается, если данные не адаптированы, чтобы не потерять операции молча. Не запускать прежний prepare-скрипт как актуальный без проверки новых правил.

## Проверка перед выдачей

1. Проверить, что в результате присутствует только названный приказ.
2. Проверить количество строк каждого журнала в рабочих материалах. На `Проблеми` вывести только конкретные расхождения, без сводки количеств.
3. Убедиться, что ПІБ и звания по ИПН взяты из ШПО.
4. Проверить, что все `Підстава` находятся в правильной колонке, а номера отпускных билетов и удостоверений не остались в тексте основания.
5. Проверить даты продовольственного обеспечения по правилу выше.
6. Проверить отсутствие ошибок формул и визуально проверить тёмную тему, перенос текста, выравнивание и ширины.
7. Для каждого исключения проверить открытое отсутствие по ІПН: командировка закрывается датой исключения + 1, СЗЧ — фактической датой возврата с дополнительным событием `Повернення до іншої частини`. При смерти вне части явная дата исключения имеет приоритет: закрытие — дата исключения + 1; только при отсутствии явного исключения использовать временную заглушку по дате смерти и закрытие датой смерти + 1. Проверить эти даты отдельно от продовольственных дат и отметить неизвестный исходный статус.
8. Сохранить новую версию без перезаписи предыдущих файлов.
